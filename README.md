# Інфраструктура Kamailio Proxy

## 🌍 Інфраструктурно

План: використовувати **2 Kamailio-сервери (USA / EU)**, які синхронізуються між собою.  
Перед ними — **GeoIP DNS**, щоб домен (наприклад, `proxy.com`) завжди вказував на найближчий Kamailio.

У кожній локації (USA, EU) встановлюється по **RTP-серверу** (або кілька), які приймають трафік на основі джерела дзвінка.

## 🔁 Логіка

На софтфоні користувач прописує:
```
proxy: proxy.com
```
Весь трафік (REGISTER, INVITE, MESSAGE, тощо) йде через `proxy.com` → потрапляє на Kamailio → і далі пересилається до `pbx.com`.

При цьому:
- REGISTER приходить на `proxy.com`, потім передається на `pbx.com`
- **На PBX зберігається IP або DNS Kamailio**, щоб якщо вхідний дзвінок надходить із транку — PBX міг переслати його назад на Kamailio
- Наприклад, якщо набирають розширення `100`, дзвінок має повернутися через Kamailio

**Оптимізація:** ідеально, щоб Kamailio також зберігав `REGISTER` локально на 1 годину — і не пересилав на PBX.

## 📞 Маршрути SIP

```
INVITE з Exten   → Kamailio → PBX
INVITE з PBX     → Kamailio → Exten
```

Усі інші SIP-методи (OPTIONS, BYE, MESSAGE...) — аналогічно.

## 🧪 HOWTO (тестовий виклик pjsua)

```bash
pjsua --null-audio --no-tcp --outbound sip:proxy.com;lr
```
